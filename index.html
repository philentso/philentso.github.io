task-board 项目说明

一个只读的 Web 看板，用来查看 task-pipeline 命名空间里流水线的运行情况。项目代码仓库地址为 https://github.com/philentso/philentso.github.io, 页面标题为 Myproject · mp-task-board。

项目是什么

  • 后端：Python + FastAPI，通过 Kubernetes API 读取 CronJob、Job、Pod、Deployment 等资源，整理后提供给页面。
  • 前端：纯 HTML、JS、CSS，没有框架，不需要编译。
  • 部署：打成 Docker 镜像，以 Deployment 的方式跑在集群里，通过 Service 和 Ingress（task-board.mp.com）访问。程序没有任何写权限。

页面有 4 个标签页：

标签页内容
任务总览每个 CronJob 的调度、下次运行、成功率、最近失败原因，以及调度异常标记
运行中 PodRunning 和 Pending 的 Pod，未就绪的排在最前，带重启次数和最近重启原因
最近执行最近的 Job，含耗时、重试次数和失败原因
常驻服务Deployment、StatefulSet、DaemonSet、Service

整体工作流程

关键点：浏览器请求不会触发访问 k8s，只读内存里已经算好的结果。这是解决页面卡顿的核心。

config.py：配置

只做一件事：读环境变量并给默认值。_bool() 把 "1"、"true"、"yes"、"on" 当作真。

环境变量默认值作用
NAMESPACEtask-pipeline要查看的命名空间
DISPLAY_TZAsia/Shanghai页面显示时间用的时区
COMPANY_NAME / PIPELINE_NAMEMyproject / mp-task-board页面标题
REFRESH_INTERVAL5后台每隔几秒刷新一次快照
K8S_TIMEOUT25访问 k8s 的读超时（秒）
RECENT_PER_CJ20每个 CronJob 统计最近多少个 Job（算成功率）
RECENT_JOBS_LIMIT300“最近执行”页最多返回多少条
ENABLE_LOGS0是否开启日志查看
LOG_MAX_BYTES512KB单次日志最大体积
UI_USER / UI_PASS空两个都设置才启用 Basic 登录

k8s_client.py：访问 k8s

名字说明
_build_clients()先尝试用集群内的 ServiceAccount 登录（load_incluster_config），失败就读本地 ~/.kube/config，所以本地和集群里都能跑
BATCH, CORE, APPS三类 API 客户端：Job 和 CronJob 属于 batch，Pod 和 Service 属于 core，Deployment 等属于 apps
_list(fn)调用某个“列出资源”的函数，拿到原始响应（_preload_content=False）后自己 json.loads，比 SDK 转成对象快很多
_LOADERS一张字典：名字对应各自的 list 函数，共 7 项
fetch_all()用线程池并行拉这 7 类资源，返回 {"cronjobs": [...], "jobs": [...], ...}

aggregator.py：数据整理

最长的文件。输入是 k8s 原始 dict，输出是页面直接能用的数据。

小工具函数

函数说明
_g(d, "a", "b")逐层取值，中间缺了就返回默认值，不会报错
_ts(s)把 k8s 的时间字符串转成秒级时间戳
_dur(start, end)两个时间戳相减，得到耗时
_short_image / _first_image取容器镜像并缩短显示：去掉仓库域名，把长 digest 缩成 8 位
_next_run用 croniter 算下次触发时间，按 CronJob 自己的时区算，没写就是 UTC
_cron_gap算未来 12 次触发之间的最大间隔，用来判断“多久没调度算异常”

Pod 相关

函数说明
_job_name_of_pod从 Pod 的标签里找它属于哪个 Job
_pod_term_reason找 Pod 里第一个“非 0 退出”的容器原因，例如 OOMKilled(exit 137)
_pod_status仿 kubectl 的 STATUS 列，返回状态、就绪数（如 0/1）、是否全部就绪
_workload_of判断 Pod 归属：Job 归到 CronJob，ReplicaSet 归到 Deployment（去掉末尾 hash）

Job 和 CronJob

函数说明
_job_phase根据 Job 的 conditions 判断 Success Failed Running 或 Pending
_job_view给每个 Job 生成页面用的视图：状态、起止时间、耗时、失败原因、最新的 Pod 名。失败 Job 的结束时间取失败那一刻
_cronjob_of判断某个 Job 属于哪个 CronJob
build_cronjobs为每个 CronJob 汇总成功率、最近失败、下次运行时间，并判断调度异常：Forbid 策略下 Job 跑得比周期还长标 blocked，超过 2 个周期没新 Job 标 stale

页面数据

函数说明
build_pods生成“运行中 Pod”列表（包含 Pending 和未就绪的），没就绪的排最前，并带最近一次重启的原因和时间
_match_pods / _pod_stats / _replicas按 Deployment 的标签选择器找到它的 Pod，统计运行数、重启数
build_workloads生成 Deployment、StatefulSet、DaemonSet、Service 四张表
build_overview总入口：依次调用上面所有函数，再汇总出顶部卡片的计数和分组统计，返回最终数据

main.py：入口

部分说明
Snapshot / SNAP内存里存快照的地方，state 保存（JSON 字节、gzip 字节、生成时间），error 保存最近一次刷新失败的原因
_refresh_loop()后台线程里的无限循环：拉数据，整理，转 JSON，存快照，再睡到下一个周期。出错只记录原因，不退出
lifespan程序启动时把 _refresh_loop 作为后台线程开起来
basic_auth中间件：设置了 UI_USER 和 UI_PASS 时，每个请求先检查登录（/healthz 除外），密码用 compare_digest 比较，防止通过响应时间猜密码
GET /返回 index.html
GET /healthz健康检查，给 k8s 的探针用
GET /api/overview返回快照。浏览器支持 gzip 就返回压缩版；没有快照返回 503；响应头带 X-Snapshot-Age（数据多旧）和 X-Snapshot-Error（刷新失败原因）
GET /api/pods/{name}/logs读 Pod 日志，仅 ENABLE_LOGS=1 时可用。会校验 Pod 名格式，限制行数（最多 5000）和体积
/api/docsFastAPI 自动生成的接口文档页面

前端文件

  • index.html：页面骨架，包括顶部标题和刷新开关、提示条、统计卡片、4 个标签页的表格和筛选框、日志弹窗。
  • app.js，按功能分段：
    • 格式化时间和耗时，esc() 对文本做转义。
    • 每个标签页一个渲染函数：renderCronjobs、renderPods、renderJobs、renderWorkloads。
    • refresh() 拉数据：上一次没回来不发下一次，20 秒超时，标签页隐藏时暂停轮询。
    • 日志弹窗：openLogs、loadLogs。
    • 事件绑定统一挂在 document 上，因为表格每次重绘，挂在行上会失效。
  • style.css：卡片、表格、徽章（成功绿、失败红、运行黄）、日志弹窗样式。

部署清单

文件说明
Dockerfile基于 python:3.11-slim，安装依赖，拷贝 app，用 uvicorn 启动。只能 1 个 worker，因为后台刷新线程每个进程各跑一份，开多个只会重复访问 k8s
requirements.txtfastapi（Web 框架）、uvicorn（运行它的服务器）、kubernetes（k8s SDK）、croniter（解析 cron 表达式）、tzdata（时区数据）
deploy/rbac.yaml给程序一个 ServiceAccount，只授予读取 jobs、cronjobs、pods、services、deployments 等的权限，外加读日志（pods/log）。程序没有任何写权限
deploy/deployment.yamlDeployment 里是环境变量、资源限制、健康探针；Service 是 ClusterIP，80 端口转到容器 8080
deploy/ingress.yaml把 task-board.mp.com 转发到 Service

本地运行

需要 Python 3.10 以上，并且这台机器的 kubectl 能连上集群。程序会自动读 ~/.kube/config。

  1. 建一个独立的 Python 环境，依赖只装在里面，不污染系统： 
    cd task-board-src
python3 -m venv .venv
source .venv/bin/activate
  2. 安装依赖： 
    pip install -r requirements.txt
  3. 确认能连集群，这一步不通，页面一定没数据： 
    kubectl -n task-pipeline get cronjob
  4. 启动，想看日志就加上 ENABLE_LOGS=1： 
    ENABLE_LOGS=1 uvicorn app.main:app --host 127.0.0.1 --port 8080
  5. 浏览器打开 http://127.0.0.1:8080。停止服务按 Ctrl+C。

app.main:app 的意思是：app 目录下 main.py 文件里名叫 app 的对象。

现象原因和处理
No module named 'app'目录不对，要在含有 app 文件夹的那一层执行 uvicorn
找不到 kubeconfig这台机器没有 ~/.kube/config，先让 kubectl 能用
页面顶部提示 403 Forbidden你的 kubeconfig 账号没有读该命名空间的权限
显示“正在生成第一份数据”正常，等几秒，第一次拉数据需要一点时间

部署到集群

  1. 创建命名空间（如果还没有）： 
    kubectl create namespace task-pipeline
  2. 构建并推送镜像，然后把 deploy/deployment.yaml 里的镜像名和 tag 改成实际值。
  3. 依次应用清单： 
    kubectl apply -f deploy/rbac.yaml
kubectl apply -f deploy/deployment.yaml
kubectl apply -f deploy/ingress.yaml
  4. 验证。最后一条会走 Ingress，不用先配 DNS 就能测试： 
    kubectl -n task-pipeline get deploy,svc,ingress
kubectl -n task-pipeline logs deploy/task-board
curl -H 'Host: task-board.mp.com' http://<节点IP>/
域名对外可访问后，建议先创建登录用的 Secret（task-board-auth），再把 ENABLE_LOGS 改成 "1"。Basic 认证在 HTTP 下密码是明文，最好配上 HTTPS。
Ingress 没写 ingressClassName，会走集群默认的控制器（k3s 默认是 traefik）。如果装了多个控制器，用 kubectl get ingressclass 查看名字，再在 ingress.yaml 里取消注释并填上。

读 Python 代码的几个写法

写法含义
def f():定义函数；async def 是异步函数，Web 接口里不做耗时操作时用它
d.get("k")取字典的值，没有这个键就返回 None，不会像 d["k"] 那样报错
[x for x in 列表 if 条件]列表推导式：从列表里挑出满足条件的元素，组成新列表
f"{a}/{b}"f-string，把变量直接嵌进字符串
try / except / finallytry 里出错就跳到 except；finally 里的代码无论成败都会执行
@app.get("/路径")装饰器：浏览器用 GET 访问这个路径时，调用下面这个函数
with 资源:在这个代码块里使用某个资源（如线程池），结束时自动清理
